# AI Job Hunt OS MVP Screen Plan

## このドキュメントの目的

このドキュメントは、AI Job Hunt OS v1.0 MVP で必要な画面構成を整理するための設計メモです。

v1.0 MVP では、AI 機能や高度な検索機能よりも先に、就活情報を人が見て管理しやすい状態にすることを優先します。中心になるデータは Company です。Company に Task と InterviewLog を紐づけることで、応募先ごとの進捗、次にやること、面接の振り返りを一つの流れで確認できるようにします。

このドキュメントは初期の画面計画を残すものです。現在は、この初期案のうち Dashboard、Company 一覧、Company 詳細、Company 作成・編集、Task 一覧、Company 詳細画面内での Task / InterviewLog 操作まで実装済みです。

一方で、InterviewLog 一覧画面は現在未実装です。以下で InterviewLog 一覧画面に触れる箇所は、現在の実装済み機能ではなく初期案または将来案として扱います。

## 1. v1.0 MVP の画面案

初期案では、v1.0 MVP の基本構成として以下を想定していました。

- ダッシュボード: 実装済み
- 企業一覧: 実装済み
- 企業詳細: 実装済み
- 企業作成・編集: 実装済み
- Company 詳細画面内の Task 作成・編集・完了切り替え・削除: 実装済み
- Company 詳細画面内の InterviewLog 表示・作成・編集・削除: 実装済み
- タスク一覧: 実装済み
- Task 一覧画面での一般 Task 作成: 実装済み
- 面接ログ一覧: 現在は未実装

これらの画面は、企業管理、選考ステータス管理、タスク管理、面接ログ管理、全体進捗の確認を実現するために必要です。

## 2. 各画面の役割

### ダッシュボード

就活全体の状態を最初に確認する画面です。

複数の企業に応募していると、どの企業がどの選考段階にあるのか、次に何をすべきかが見えにくくなります。ダッシュボードでは、全体の進捗と直近の対応事項をまとめて表示し、ユーザーが次の行動を判断しやすくします。

### 企業一覧

応募先企業を一覧で確認する画面です。

AI Job Hunt OS の中心は Company です。企業一覧では、登録済みの応募先を見渡し、選考ステータスや志望度などを確認します。最初の MVP では、細かい検索やフィルターよりも、登録した企業をシンプルに一覧できることを優先します。

### 企業詳細

1 社ごとの情報を確認する画面です。

企業詳細では、会社情報、選考ステータス、関連タスク、面接ログをまとめて表示します。Company に Task と InterviewLog を紐づけることで、「この企業について次に何をするか」「過去の面接で何を話したか」を同じ画面で確認できます。

### 企業作成・編集

応募先企業の情報を登録・更新する画面です。

MVP では、まず自分が応募している企業を記録できることが重要です。企業情報を登録できないと、タスクや面接ログを紐づける対象がなくなるため、企業作成は早い段階で必要になります。

### タスク一覧

現在は実装済みです。

就活で必要な作業を一覧で確認する画面です。

提出期限、面接準備、企業研究、応募書類の修正など、就活では企業ごとに小さなタスクが発生します。タスク一覧では、ログインユーザーの全 Task を未完了 / 完了に分けて確認できます。Company に紐づく Task は関連 Company へのリンクを表示し、Company に紐づかない一般 Task も作成・編集・削除できます。

### タスク作成・編集

Company 詳細画面内で、Company に紐づく Task の作成・編集・完了切り替え・削除は実装済みです。Task 一覧画面では、企業に紐づかない一般 Task の作成・編集・削除も実装済みです。

タスクを登録・更新する画面です。

タスクは Company に紐づけられるようにします。これにより、「A 社の面接準備」「B 社のES提出」のように、何のための作業なのかを明確にできます。

### 面接ログ一覧

現在は未実装です。以下は将来案です。

面接の記録を一覧で確認する画面です。

面接後の振り返りは、次の面接準備や志望度の判断に役立ちます。面接ログ一覧では、過去の面接内容を時系列で確認できるようにします。

### 面接ログ作成・編集

Company 詳細画面内で、Company に紐づく InterviewLog の表示・作成・編集・削除は実装済みです。企業をまたいだ InterviewLog 一覧画面は現在未実装です。

面接の内容や振り返りを記録する画面です。

面接ログは Company に紐づけます。企業ごとに面接で聞かれたこと、答えたこと、反省点、次回に向けたメモを残すことで、情報が散らばらないようにします。

## 4. 最初に実装する画面

最初に実装する画面は、企業一覧と企業詳細です。

理由は、AI Job Hunt OS の中心データが Company だからです。企業一覧で応募先全体を確認し、企業詳細で 1 社ごとの選考ステータス、タスク、面接ログを確認できるようにすると、このアプリの基本体験が伝わりやすくなります。

実際の進行では、最初にモックデータで画面構成と表示項目を確認し、その後 Prisma 7 + PostgreSQL に移行しました。現在は Company CRUD、Company 詳細画面内での Task / InterviewLog 操作、Dashboard DB 集計まで実装済みです。

## 5. 後回しにする画面

v1.0 MVP では、以下の画面や機能は後回しにします。

- AI による文章生成画面
- AI による面接対策画面
- カンバン形式の選考管理画面
- 高度な検索・フィルター画面
- 学習計画画面
- ポートフォリオ進捗画面
- カレンダー連携画面
- 外部サービス連携画面
- 通知設定画面
- 複数ユーザー共有画面

これらは便利ですが、最初から入れると MVP の目的が広がりすぎます。まずは、企業、選考ステータス、タスク、面接ログを正しく管理できる状態を作ります。

## 6. 画面構成を決めるうえでの注意点

- Company を中心に考える
- Task と InterviewLog は Company に紐づける
- 最初から高機能にしすぎない
- 一覧画面と詳細画面の役割を分ける
- ダッシュボードは全体確認、企業詳細は個別確認に使う
- モックデータで画面の見え方を確認してから DB 実装へ進む
- GitHub で読まれたときに、なぜその画面が必要なのかが伝わるようにする
- AI 機能は、元になる就活データが整理できてから追加する
- カンバンや検索・フィルターは、基本画面ができてから検討する
- 入力項目を増やしすぎず、MVP で必要な情報に絞る

画面構成では、最初から完成形を目指すよりも、就活情報を迷わず入力し、確認できることを優先します。

## 7. 今後の実装順序メモ

以下は初期の実装順序メモです。1、2、3、6、7、8、9、10 は形を変えつつ実施済みです。ただし、7 と 8 は Company 詳細画面内での実装であり、独立した一覧画面は未実装です。

1. 企業一覧画面をモックデータで作る
2. 企業詳細画面をモックデータで作る
3. ダッシュボード画面をモックデータで作る
4. タスク一覧画面を作る: 実装済み
5. 面接ログ一覧画面を作る: 現在は未実装
6. 企業作成・編集画面を作る
7. タスク作成・編集画面を作る: Company 詳細画面内で実装済み
8. 面接ログ作成・編集画面を作る: Company 詳細画面内で実装済み
9. データ構造を整理し、Prisma schema の設計に進む
10. PostgreSQL 保存と基本 CRUD を実装する

この順序にすることで、まず画面として見える価値を作り、その後でデータ保存や編集機能を段階的に追加できます。
